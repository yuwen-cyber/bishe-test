### 1.2 灌库完成的判定标准

全部满足才算灌完：

- 映射文件 `experiments\output\seed_mapping_real.json` 条数 = **700**
- `experiments\output\seed_failed.json` 为空数组 `[]`（或失败条数 0）
- MySQL：`segments = 700`，`conversations = 700`
- MinIO 桶 `multimodal` 内对象数 = **1400**（700 视频 + 700 音频）

### 1.3 中途中断 / 失败怎么办

- **进程被关掉、电脑重启、脚本报错退出**：直接重跑下面命令即可，已在映射表里的编号会自动跳过，从断点接着灌：

```powershell
.venv\Scripts\python.exe experiments\seed_real_data.py
```

- **个别条目失败**：失败清单写在 `experiments\output\seed_failed.json`，里面有原始编号和报错原因。修好对应文件/网络后，重跑上面命令会把失败的补灌进去。
- **想先试跑几条**：加 `--limit 5` 只灌前 5 条。

## 阶段三：回填查询集真值编号（编号映射）

### 3.1 为什么要这一步

数据集原始编号是 `0~700`，灌入 MySQL 后 `segment.id` 是数据库自增编号（1、2、3…），两者不一致。评测脚本是拿后端返回的 `segment_id` 跟真值匹配的，所以必须先把查询集真值里的原始编号换成数据库编号。

### 3.2 执行回填

```powershell
.venv\Scripts\python.exe experiments\remap_query_set.py
```

- 输入：`experiments\output\seed_mapping_real.json`（灌库映射）+ `experiments\query_set.json`（原始真值）
- 输出：`experiments\output\query_set_db.json`（回填后的评测查询集）

### 3.3 检查回填结果

脚本结束会打印：

- `映射表条目数`：应为 700
- `相关项合计 / 成功回填`：两者应相等
- 若出现 `[警告] 有 N 条查询包含未映射到数据库的原始编号`：说明有片段没灌进去，先回阶段一补灌，再重跑本脚本。

> 原始 `query_set.json` 不会被修改，回填结果单独放在 `output\query_set_db.json`。

## 阶段四：跑四模式检索评测

### 4.1 前置确认

- 后端服务在运行（`http://localhost:8000` 健康检查返回 `{"status":"ok"}`）：

```powershell
(Invoke-WebRequest "http://localhost:8000/api/health" -UseBasicParsing -TimeoutSec 5).Content
```

### 4.2 运行评测脚本

> 注意：必须显式指定回填后的查询集 `query_set_db.json`，不能用默认的原始 `query_set.json`。

```powershell
.venv\Scripts\python.exe experiments\run_eval.py --query-set experiments\output\query_set_db.json
```

脚本会对 50 条查询 × 4 个配置依次检索：

| 配置名 | 接口 | 查询扩展方式 |
|---|---|---|
| `baseline` | `/api/baseline/search` | MySQL ngram 全文检索，不做向量 |
| `advanced_plain` | `/api/advanced/search?expand=none` | 纯向量检索，不扩展 |
| `advanced_lexicon` | `/api/advanced/search?expand=lexicon` | 向量 + 情感词典规则扩展 |
| `advanced_llm` | `/api/advanced/search?expand=llm` | 向量 + 大模型语义扩展 |

### 4.3 产出文件

写到 `experiments\output\`：

- `metrics.csv`：每个配置的汇总指标（4 行，对应上面 4 个配置）
- `per_query_detail.csv`：每条查询 × 每个配置的命中明细

### 4.4 指标怎么读

| 指标 | 含义 | 越高越好 |
|---|---|---|
| `recall@1` / `@5` / `@10` | 前 1 / 5 / 10 条里命中相关片段的比例 | 是 |
| `mrr` | 第一个命中结果的排名倒数（排得越靠前越高） | 是 |
| `ndcg@10` | 考虑排名位置的排序质量 | 是 |
| `avg_time_ms` | 平均检索耗时（毫秒） | 越低越好 |

> 注意：后端两个检索接口当前最多返回 top 3，所以 `recall@5 / recall@10 / ndcg@10` 实际最多只能计入 3 条命中，对比时四个配置口径一致即可。

### 4.5 四模式对比怎么写进论文

- `baseline` vs `advanced_plain`：体现**向量语义检索**相对关键词全文检索的提升。
- `advanced_plain` vs `advanced_lexicon`：体现**词典查询扩展**的增益。
- `advanced_lexicon` vs `advanced_llm`：体现**大模型语义扩展**相对规则扩展的增益。
- 同时记录各配置 `avg_time_ms`，说明扩展带来的召回提升与耗时代价。

## 阶段五：可选增强（临近毕设再做，当前不影响出基线指标）

### 5.1 音频 / 图像真实编码器（当前走 mock 降级）

当前 `.env` 里 `USE_REAL_AUDIO`、`USE_REAL_IMAGE` 未开启，音频/图像向量是占位哈希向量。若要做跨模态检索的完整演示：

- 在 `.env` 把对应开关改为 `true`，重启后端；
- 首次会下载 Wav2Vec2（音频，768 维）/ CLIP（图像，512 维）模型，吃内存；
- 改完需要重灌数据（或跑 `rebuild_milvus.py` 重新算向量）。

> 建议：先把文本主线的四模式指标跑出来，跨模态真模型作为后续加分项。

### 5.2 DeepSeek 大模型查询扩展（llm 模式）

- `query_expander.py` 的 `llm` 模式：配置了 `DEEPSEEK_API_KEY` 就真调 DeepSeek；**没配 key 或调用失败会自动降级成词典扩展**。
- 想先纯免费跑：把 `.env` 里 `DEEPSEEK_API_KEY` 留空，`advanced_llm` 会自动退化为 lexicon。
- 临近毕设要出真实 LLM 扩展对比时，再填回 key 重跑评测即可。
- 50 条查询每条只调一次，费用很低。

### 5.3 关于情绪识别偏差

TTS 合成语音经情绪模型识别，个别片段情绪标签会与标注有偏差（如标注"悲伤"判成"喜悦"）。这是合成语音 + 情绪模型的固有现象，ASR 文字识别是准的。该偏差会真实反映在指标里，属于实验结果，论文中可作为"合成语音情绪识别局限"的讨论点。

## 附：常见故障排查

| 现象 | 处理 |
|---|---|
| 后端启动后原生崩溃退出（0xC0000005） | 清掉残留 uvicorn/python 进程，用 `.venv` 不带 `--reload` 干净重启 |
| 灌库中途断了 | 重跑 `seed_real_data.py`，自动跳过已灌条目 |
| 某几条一直失败 | 看 `seed_failed.json` 的报错；多为音视频文件损坏或后端临时抖动，修好后重跑续传 |
| 评测召回全为 0 | 先确认用的是 `query_set_db.json`（回填后的编号），不是原始 `query_set.json` |
| Milvus 与 MySQL 条数对不上 | 跑 `rebuild_milvus.py` 重建向量 |
| 检索返回中文乱码 | 多为终端编码显示问题，库里存的是 UTF-8；用接口 JSON 或前端查看即为正常中文 |
