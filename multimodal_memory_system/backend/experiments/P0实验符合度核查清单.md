### 实验 3 · 结构化精确与关键词检索测试（95%）

**已完成**
- 查询覆盖：结构化精确 12 条、关键词 12 条（文档要求各 8~10 条，数量够）。
- 延迟：四模式表含 `avg_time_ms`，并新增客户端实测 P50/P95/最大值。
- 基线接口：`/api/baseline/search`（MySQL ngram 全文 + 情绪/时间过滤）。
- **Precision/F1 已补齐**：`run_eval.py`、`run_hybrid_eval.py` 均输出 Precision@1/5/10、F1@1/5/10，与 Recall 同表；已抽条手算复核一致。
- **按类型分组已拆**（`eval_by_type.py` → `metrics_by_type.csv` / `.md`）：四类场景分别出表。

**关键发现与处理（必须写进论文/局限）**
- 原查询集里 12 条「userXXX + 情绪」类查询，因数据集 700 条均为「一上传=一会话=一片段」，**没有说话人（user）维度**，
  该组在原口径下不可能命中；未采用「按答案倒推 user 字段」的做法（那会构成标注泄漏）。
- **已改为可判定的组合条件查询并实测**：`build_structured_queries.py` 生成 20 条（单条件 10、多条件组合 10），
  真值由 SQL 条件机械判定（含日期锁定，避免跨日离群片段混入）；`run_structured_eval.py` 对比三方案
  （`metrics_structured.csv`、`structured_eval.md`）：
  - 精确过滤（基准）：集合级 P/R/F1 全 1.0，P95 4.33ms
  - 纯关键词 LIKE：P 0.3786 / R 1.0 / F1 0.5432（仅 3 条含关键词查询适用）
  - 纯向量：P 0.1313 / R 0.6573 / F1 0.1882 —— 印证「纯向量在结构化约束上不如基准方案」
- **系统接口能力已补齐**：原 `/api/baseline/search`、`/api/advanced/search` 强制要求自然语言 q（且带 0.5 相似度阈值），
  无法表达「只按条件查」。新增独立路由 `app/routers/structured.py`（`GET /api/structured/search`，`main.py` 两行注册，
  不改原有接口），支持情绪/时间/关键词/时长任意组合。
  接口层验证（`run_structured_http_eval.py` → `structured_http_eval.md`）：**20/20 条返回集合与真值完全一致**，
  客户端 P50 11.62ms / P95 30.52ms（该路由只查 MySQL、无模型推理）。
- **总体口径已修正**：`recompute_overall_metrics.py` 输出 `metrics_overall_adjusted.csv/.md`，
  给出「原口径 50 条」与「有效口径 38 条（剔除 12 条不可判定查询）」两套数字，后者明显更高
  （如 hybrid_weighted R@10 0.2717 → 0.3399），论文主表建议用有效口径并加表注。

**未完成 / 缺口**
1. 说话人（user）维度缺失：要真正支持「某人的片段」需改数据模型与采集流程（属业务改造，未做，写局限）。
2. 后端需重启才会加载新路由（`main.py` 已注册）；当前 8000 端口实例是重启前的旧进程。

## 四、可直接写进论文的现状结论

- 数据规模 700 片段 / 50 查询，四类场景覆盖；检索真值 157 项。
- 混合检索召回广度最广（41/50 命中），加权混合 R@10 0.2717；纯向量头部精度较好。
- **延迟（已预热排除冷启动）**：四模式 HTTP 端到端 P50/P95 —— baseline 20.9/32.9ms、
  advanced_plain 62.3/74.4ms、advanced_lexicon 60.9/70.9ms、advanced_llm 61.6/73.5ms；
  混合离线口径 P95 —— keyword 2.93ms、vector 21.4ms、hybrid 24.2ms。
  后端自报检索耗时 2.28 / 38.7 / 40.1 / 40.0ms，与客户端差额主要为 HTTP 与 JSON 序列化开销。
- **分组差异**（详见 `metrics_by_type.md`）：
  - 原 12 条「userXXX」类查询缺说话人维度、不可判定；已另建 20 条组合条件查询实测：精确过滤 P/R/F1=1.0、纯向量 P=0.13。
  - 关键词 12 条：向量最强，R@5 0.3472、R@10 0.5417、NDCG 0.3814；加权混合 R@10 0.5486 略高但 NDCG 0.3771 略低。
  - 语义 18 条：R@10 最高 0.3148（hybrid 与 keyword），MRR 最高 0.3023（vector），R@1 最高 0.0556（vector / advanced_plain）。
  - 跨模态 8 条：整体偏弱，R@10 最高 0.125（hybrid_weighted），R@5 最高 0.0833（vector），是后续主要改进方向。
- 模态消融：纯文本为主力，单用音频/图像跨模态弱，融合小幅增益，加情绪 MRR 最高。
- 融合策略消融：拼接+降维 R@10 0.2900、加权平均 0.2867、仅文本 0.2700；两种融合均略优于单文本（约 +0.02），拼接降维需额外拟合 PCA 且查询侧零填充，加权平均更轻量，建议作默认融合。
- 性能：三档端到端 ~13.2ms、P95 ~17ms，检索随规模近子线性，内存增量平缓，无外部 API 成本。
