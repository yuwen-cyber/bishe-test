# 实验 2：数据存储与回放功能测试

## 测试环境
- 元数据：MySQL `multimodal`，conversations 2230 条、segments 2230 条
- 对象存储：MinIO 桶 `multimodal`，对象 4524 个
- 向量库：Milvus 集合 `segments`
- 前端：`ResultCard.vue`（video + audio 双通道，播放时音频同步）

## 结果汇总

| 指标 | 计算方式 | 分子/分母 | 结果 |
|---|---|---|---|
| 存储成功率 | MinIO 中存在的音视频对象数 / 应有对象数 | 4460/4460 | **100.00%** |
| 数据一致性 | MySQL↔MinIO↔Milvus 三处 ID 全部对齐则为 1，否则 0 | 1/1 | **100.00%** |
| 回放成功率 | 抽样 presigned URL 取流成功数 / 抽样请求数 | 100/100 | **100.00%** |

## 口径与局限

- 存储成功率是**事后核验**（对象是否存在），不是重新灌库重跑；写入环节的记录来自 `seed_real_data.py` 的 700/700、0 失败。未重跑是为了避免往正式数据集里插入重复记录。
- 回放测试只取前 2KB，验证的是「能否取到流」；完整解码/播放流畅度属前端体验，由 TC-06 人工确认，未做自动化帧级校验。
- 会话/片段共 2230/2230 条，其中 2 条为早期联调残留（id 701、702，时间戳 11-15/11-16），正式评测数据 700 条；本表核验覆盖全部记录，未剔除，便于说明「库里有什么就查什么」。
- 技术栈为 MySQL + MinIO + Milvus；导师文档允许轻量化（SQLite + 本地文件），本文选择重型栈是为贴合「多模态对象 + 向量库」的实际部署，论文需说明与轻量方案的差异。
