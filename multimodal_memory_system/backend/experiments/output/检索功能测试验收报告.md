## 四、混合方案权重机制（导师点名"须彻底搞清"）

**实现位置**：`backend/app/routers/hybrid.py`

1. **不是把两路分数加权相加，而是加权 RRF（Reciprocal Rank Fusion）**
   `score(sid) = Σ w_i / (k + rank_i)`，`k = 60`，`_W_SQL = 1.0`，`_W_VEC = 2.0`，两路各召回 50 个候选，融合后按 `is_demo` 做二级排序，取 top3。
2. **为什么不能直接加分数**：SQL 路径给的是全文相关度（数值无上界、依赖词频），向量路径给的是余弦相似度（[-1,1]），**两者量纲不同，直接加权没有意义**；RRF 只用排名，天然消掉量纲。
3. **为什么是 1:2**：`experiments/run_weight_sweep.py` 扫了 25 组 (w_sql, w_vec) 网格，每组 50 查询：

| 权重比 | R@10 | MRR | NDCG@10 |
|---|---|---|---|
| 1:2（当前） | **0.2467** | 0.2246 | 0.1703 |
| 0.5:1 | 0.2467 | 0.2246 | 0.1703 |
| 1.5:3 | 0.2467 | 0.2246 | 0.1703 |
| 0.5:3（6:1 反向） | 0.2400 | **0.2321** | — |

4. **关键性质（答辩可讲）**：RRF 对权重**整体缩放不变**，1:2 与 0.5:1 结果逐位相同，所以真正起作用的只有一个自由度——"比值"。当前 1:2 在 R@10 与 NDCG 上并列最优；6:1 只把 MRR 抬高 0.0075 却让 R@10 掉 0.0067，不划算。
5. **已知局限**：权重是全局固定超参，不随查询类型自适应（如"纯情绪查询"更适合压向量、"精确时间查询"更适合压 SQL）。这一点已写入报告，作为后续改进项。

## 五、三个"当前问题"的复现与归因

### 5.1 本地保存音视频耗时不稳定 → 已定位

单组件单进程实测（`experiments/perf_breakdown.py`）：

| 组件 | 均值 | 区间 / 说明 |
|---|---|---|
| MinIO 上传 | 27.4ms | 17.6–48.4（σ=10.0） |
| MinIO 下载 | 14.3ms | — |
| 文本编码（bge） | 36.3ms | 冷启动 **31.1s** |
| 音频编码 | 109.6ms | — |
| 图像编码（CLIP） | 3683.7ms | 首条 **20578.9ms**，之后约 300ms |
| 语音识别（FunASR） | 1437.6ms | 1051.2–2508.7（σ=505.1），冷启动 **50.8s** |
| 情绪识别（emotion2vec） | 未取得单条值 | 导入日志显示约 50s/条；本轮单进程加载直接崩溃（0xC0000005，可用内存仅 5.1GB） |

**结论**：耗时不稳定的主因是**模型冷启动（首个请求付几十秒加载成本）+ ASR 与情绪模型本身波动**，磁盘 IO 与网络只占几十毫秒。要改善就得做**模型常驻预热 + 上传异步化（先落盘返回、后台补特征）**。

一个具体缺陷：图像编码首条 20.6s，是因为 `USE_REAL_IMAGE=false` 导致 `warmup()` 跳过模型加载，直到第一条真实编码才触发加载。

### 5.2 语音转文字慢 → 复现

1437.6ms/条、冷启动 50.8s。2230 条全量入库时这就是主要瓶颈。

### 5.3 语音转文字内容缺失 → 未复现

30 条随机抽样（seed=20261126）比对"ASR 输出字数 / 库中文本字数"：

| 指标 | 值 |
|---|---|
| ratio 均值 | **0.991** |
| 最小 / 最大 | 0.92 / 1.05 |
| 标准差 | 0.025 |
| ratio < 0.6 的条数 | **0** |
| 空结果 | **0** |

即当前数据里不存在"识别内容缺失"。若导师观察到缺失，需要具体失败样本（哪条、哪段音频）才能定性——可能出现在特定音频格式、长音频或低信噪比片段。

## 六、本轮发现的缺陷

### 6.1 已修复：`/api/structured/search` 参数名不一致

- **现象**：`/baseline`、`/advanced`、`/hybrid` 用复数 `emotions`，`/structured/search` 只认单数 `emotion`。传 `emotions=喜悦` 被**静默忽略**，返回混合情绪结果。
- **影响**：结构化接口的筛选功能实际不可用（不报错、不生效，最容易被答辩问到）。
- **修复**：`app/routers/structured.py` 增加 `emotions` 作为别名，两者都传取并集。
- **验证**：复数单传 / 单数单传 / 两者同传三种情况均返回 10 条且全为"喜悦"；不传筛选时返回混合情绪。前端 `SearchCompare.vue` 只用 baseline/advanced/hybrid（均传 `params.emotions`），不调 structured，改动无破坏。

### 6.2 未修：静默失败（建议加校验）

| 用例 | 现状 | 建议 |
|---|---|---|
| 无效情绪标签（如"开心"） | 200 + 0 条，无提示 | 返回 422 并列出合法标签 |
| 起止时间颠倒 | 200 + 0 条，无提示 | 返回 422「start 晚于 end」 |
| 空查询 | 422 `string_too_short` | 合理，保持 |
| 超长查询（200 字） | 200 + 3 条 | 可接受 |

### 6.3 未修：64 个孤儿对象

MinIO 2262 × 2 = 4524 对象，DB 2230 × 2 = 4460 → **多 64 个**（32 条 × audio+video，来自早期重复上传）。不影响可检索数据，但会让"存储对象数"与"记录数"对不上，答辩被问需提前准备口径。

### 6.4 ⚠️ 未修（重要）：影片噪声 227 条的向量与主库不同源

分层抽样审计（每层 10 条，`experiments/verify_vector_space_audit.py`）：

| 数据层 | 图像向量来源 | 抽样结果 |
|---|---|---|
| 正式（1–700） | 真实 CLIP | 10/10 real |
| 场景噪声（701–2032） | 真实 CLIP | 10/10 real |
| **影片噪声（2033–2259）** | **哈希 mock** | **10/10 mock**（与真实 CLIP 余弦 ≈ -0.05，与运行时 mock 余弦 = 1.000） |

**成因**：227 条影片噪声是批量导入时在 `USE_REAL_IMAGE=false` / `USE_REAL_AUDIO=false` 下写入的，落进 Milvus 的是 mock 哈希向量；而 .env 当前仍是 `USE_REAL_IMAGE=false`、`USE_REAL_AUDIO=false`，**新上传的数据也会写 mock 向量**。

**影响**：
- 图像/音频相似度在 227 条噪声行与其余 2003 行**不可比**，跨模态"查得准"对这部分数据不成立；
- 离线评测走 `_encode_real`，指标本身不受污染，但**线上入库路径与离线评测路径不同源**，属口径不一致；
- 干扰检索时，这 227 条会以"无意义相似度"参与排序。

**修复方案（现成脚本已写，未执行）**：`experiments/rebuild_film_vectors.py` 只重建这 227 行的 image/audio 向量后 upsert 回 Milvus，预计 227×(300ms+110ms) ≈ **95 秒**；重建后需重跑 image 相关消融指标（`run_ablation.py`）刷新数字。
**另一条路线**：把 `.env` 改为 `USE_REAL_IMAGE=true / USE_REAL_AUDIO=true`，让线上与离线统一为真实模型（代价：单条上传耗时增加约 0.4s，且首条冷启动 20s）。

## 八、答辩口径备忘（被问到时怎么答）

1. **"数据量多少？"** 2230 条：正式 700（7 类情绪各 100）、场景噪声 1300、影片噪声 227（无人物、全片字幕/风景/空间站）、自录 3。噪声统一显示「噪声」徽标。
2. **"为什么要有噪声？"** 模拟真实对话里大量无情绪、无信息的片段，检验检索在噪声中的抗干扰能力；消融显示加噪声后 full 口径 R@10 从 0.270 降到 0.242，这个差值本身就是论文的讨论点。
3. **"权重怎么定的？"** 加权 RRF、1:2、k=60，25 组网格扫出来的，且 RRF 对权重缩放不变，真正有效的只有一个比值自由度（§四）。
4. **"查得准怎么证明？"** 三种口径分开讲：结构化精确查询 F1 0.8262 / MRR 0.5697；混合检索 R@10 0.2467（有效查询 0.3070）；纯关键词 baseline 只有 0.045–0.0617 → 提升幅度约 4–5 倍。
5. **"ASR 慢怎么办？"** 已量化 1.4s/条、冷启动 50.8s，方案是模型常驻预热 + 上传异步化；至于"内容缺失"，30 条抽样完整度 99.1%，需要具体失败样本才能定性。
6. **"向量怎么算的？"** 文本 bge、图像 CLIP、音频编码器、情绪 emotion2vec；**注意**：影片噪声 227 条当时用了 mock 编码器，需在答辩前重建（§6.4）。
