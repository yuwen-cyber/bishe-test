# 案例分析：语义检索的跨字面表达能力

统计口径：在同一 50 条查询集上，筛选「纯关键词（MySQL 全文）与基线 SQL 均未命中真值、而纯向量语义检索命中」的查询，作为语义检索跨字面召回的证据。共筛出 6 条，下表按查询类型优先级取前 5 条。

| # | 查询类型 | 用户查询（字面表达） | 真值片段 | 语义检索命中 | 关键词命中 | 基线命中 |
|---|---|---|---|---|---|---|
| 1 | 语义查询 | 用户说压力大快撑不住了 | 403, 407, 458 | 403 | 无 | 无 |
| 2 | 语义查询 | 今天碰到意料之外的好事 | 338, 358, 378 | 378 | 无 | 无 |
| 3 | 跨模态查询 | 声音里透着害怕和紧张 | 555, 563, 579 | 555, 563 | 无 | 无 |
| 4 | 跨模态查询 | 听起来很疲惫有气无力 | 435, 446, 454 | 435, 454 | 无 | 无 |
| 5 | 关键词查询 | 提到做饭、菜单、新菜的片段 | 206, 218, 250 | 250, 218, 206 | 无 | 无 |

## 命中片段原文（举证）

**案例 1｜查询：用户说压力大快撑不住了**

- `#403`：最近事情压得我喘不过气，白天硬撑着，晚上一个人时，特别想找人说说话。

**案例 2｜查询：今天碰到意料之外的好事**

- `#378`：今天出门发现楼下开了家新店，之前一点都没注意到挺惊喜。

**案例 3｜查询：声音里透着害怕和紧张**

- `#555`：刚才手机突然响了一声，我吓得一激灵，现在心跳还没缓过来。
- `#563`：刚才窗户外突然有个影子晃了一下，我吓得不敢动，现在还有点怕。

**案例 4｜查询：听起来很疲惫有气无力**

- `#435`：我最近特别容易累一点小事就觉得撑不住，也不知道是不是该歇歇。
- `#454`：我最近总觉得心里堵得慌，想说又说不清，只能自己慢慢消化。

**案例 5｜查询：提到做饭、菜单、新菜的片段**

- `#250`：今天邻居给了我一点自家种的菜，我做了个汤，觉得特别香。
- `#218`：今天晚饭做的特别成功，我自己都多吃了一碗，心情很好。
- `#206`：今天试着自己煮了锅汤，没想到味道还行，家里人也说好喝。

## 结论

- 这些查询的字面表述（如口语化情绪描述）与片段转写文本用词并不重合，全文检索依赖词面匹配因而全部落空；向量检索把查询与片段映射到同一语义空间后仍能召回。
- 这说明纯关键词方案的能力边界在「词面不一致」，而语义检索补的正是这块长尾，也是后续引入 SQL+向量混合检索（提升召回广度）的动机。

> 注意：以上命中均以 `output/query_set_db.json` 中的真值 `relevant_segment_ids` 判定，
> 指标只统计 top-10 内命中，与 `metrics_hybrid.csv` 口径一致。
