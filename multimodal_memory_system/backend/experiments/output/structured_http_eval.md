# 结构化查询：接口层验证（实验 3 补充）

## 目的
证明**系统接口**（`GET /api/structured/search`）能真正执行「情绪 / 时间范围 / 关键词 / 时长」任意组合的条件查询，并给出接口层客户端实测延迟。
原 `/api/advanced/search` 强制要求自然语言查询词且带 0.5 相似度阈值，无法表达「只按条件查」，故新增独立路由（不改原接口）。

## 结果
- 查询数：20 条
- 返回集合与 SQL 真值**完全一致**：20/20 条
- 集合级 Precision / Recall / F1：1.0 / 1.0 / 1.0
- 客户端延迟 P50 / P95 / max：11.62 / 30.52 / 36.65 ms

## 口径与说明
- 本测试用 FastAPI TestClient 直接挂载该路由，**不加载 ASR/Embedding 模型**（该路由只查 MySQL，不含推理），因此延迟反映的是接口 + SQL 的真实开销，与 `/advanced/search` 的向量检索延迟不可直接比较。
- 正式运行的后端需重启以加载该路由；重启后可用 `curl "http://localhost:8000/api/structured/search?emotion=悲伤&limit=5"` 自查。
- 指标为 1.0 属构造必然（真值即条件结果），此处价值在于**接口可用性 + 结果一致性 + 接口延迟**三项证据，不构成算法比较。
